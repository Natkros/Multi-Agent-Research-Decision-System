# Risk Register (project/system risk, not the runtime Risk Analyst agent)

| ID | Risk | Probability | Impact | Severity | Mitigation |
|---|---|---|---|---|---|
| R1 | LLM hallucinated citation (agent cites a source id/claim that wasn't retrieved) | Medium | High | High | Verification Gate cross-checks every citation marker against `state.sources`; report rejected and returned to Final Synthesizer if any citation is unresolvable. |
| R2 | Prompt injection via retrieved web content redirects an agent's behavior | Medium | High | High | Retrieved content is always wrapped as untrusted data in a distinct message segment; system prompts explicitly forbid treating retrieved text as instructions; guardrail scanner flags suspicious imperative-language patterns in retrieved passages before they reach the LLM context. |
| R3 | Infinite or runaway agent loop (verification ping-pong, researcher over-iterating) | Low | High | Medium | Hard caps enforced in code (not prompt-only): max iterations per agent, 3-cycle verification ceiling, wall-clock timeouts per node, independent of model behavior. |
| R4 | Cost blowout from unbounded parallel fan-out or repeated re-runs | Medium | Medium | Medium | Token budgets per agent, model routing (cheap models for extraction/classification), semantic caching, max research-question fan-out count configured per plan. |
| R5 | Search/LLM provider outage mid-run | Medium | Medium | Medium | Retries with exponential backoff (bounded), circuit breaker per provider, provider-agnostic interfaces allow failover to a secondary configured provider. |
| R6 | Source quality bias (over-reliance on high-domain-authority but low-relevance sources) | Medium | Medium | Medium | Source Evaluator scores on explicit weighted factors (not domain reputation alone); Decision Analyst and Verification Gate both check evidence diversity, not just count. |
| R7 | Contradiction Detector false positives (flags version/context differences as genuine conflicts) | Medium | Low | Low | Explicit contextual-comparison step (versions, dates, workloads, environments) before a conflict is marked "genuine" vs. "context_mismatch". |
| R8 | Vector DB / Postgres data loss or drift between them | Low | High | Medium | PostgreSQL is the system of record; Qdrant is rebuildable from PostgreSQL + the ingestion pipeline, never the sole store of any fact. |
| R9 | Scope creep — building the full spec (40 sections) before validating the core loop works | High | High | High | Phased plan (Phase 0-10) with hard exit criteria per phase; Phase 1 deliberately ships a minimal single-agent path before any multi-agent complexity. |
| R10 | Evaluation becomes purely subjective ("looks good") | Medium | Medium | Medium | Quantitative metrics defined up front (§24) and a fixed 20-question benchmark authored before Phase 9 work starts, so later phases can't quietly redefine "success". |
| R11 | Secrets leaked into source control (API keys for LLM/search providers) | Low | High | Medium | `.env.example` only, real secrets via environment/secret manager, `.gitignore` covers `.env`, CI includes a secret-scan step. |
| R12 | Sensitivity analysis and decision weights presented as more precise than the underlying evidence supports | Medium | Medium | Medium | Every score in the decision matrix carries a rationale and evidence_ids (never an unexplained number, per coding rule #33); confidence and evidence-coverage are first-class fields on the final report, not an afterthought. |
